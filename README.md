# با من ببین · Ba Man Bebin

یک پلتفرم **تماشای همزمان (Watch Party)** — فیلم و ویدیو را کاملاً همگام با دوستانت ببین، با چت زنده و واکنش‌های لحظه‌ای.

A sleek, bilingual (فارسی/English, RTL + LTR) watch-party platform. Create a room, share the link, and watch in perfect sync.

## 🖥️ روش ۲ — نصب مستقیم روی سرور (Ubuntu/Debian)

یک دستور، همه‌چیز آماده — Node.js، systemd، Nginx و SSL:

```bash
git clone <repo-url> ba-man-bebin && cd ba-man-bebin
sudo bash deploy/deploy.sh example.com you@example.com
```

اسکریپت به‌ترتیب: Node 22 نصب می‌کند → اپ را در `/var/www/ba-man-bebin` می‌گذارد →
سرویس systemd می‌سازد → Nginx را با پشتیبانی WebSocket تنظیم می‌کند → گواهی Let's Encrypt می‌گیرد.

```bash
systemctl status ba-man-bebin      # وضعیت
journalctl -u ba-man-bebin -f      # لاگ زنده
systemctl restart ba-man-bebin     # ری‌استارت
```

## 🔗 منابع ویدیو / Video sources

در اتاق، کادر بالای پلیر **هر نوع لینکی** را قبول می‌کند و خودش تشخیص می‌دهد:

| نوع | نمونه | چطور پخش می‌شود |
|---|---|---|
| یوتیوب | `youtu.be/xxxx` · `youtube.com/watch?v=` · shorts | IFrame API |
| لینک مستقیم | `https://host/film.mp4` · `.webm` · `.mkv` | تگ `<video>` (در صورت نیاز از طریق پراکسی) |
| استریم HLS | `https://host/live/index.m3u8` | `hls.js` |
| مگنت / تورنت | `magnet:?xt=urn:btih:…` · `.torrent` | WebTorrent، مستقیم در مرورگر |
| فایل محلی | انتخاب از سیستم | فقط برای خودت؛ هرگز آپلود نمی‌شود |

### 🧪 دکمه «تست پخش»

قبل از اینکه لینک را برای همه بگذاری، دکمه **تست پخش** را بزن. سرور لینک را بررسی می‌کند و
گزارش می‌دهد: در دسترس بودن، نوع محتوا، حجم فایل، پشتیبانی از seek، و اینکه آیا مستقیم
در مرورگر پخش می‌شود یا نه. اگر مشکلی باشد (لینک مرده، صفحه دانلود به‌جای فایل، فرمت
غیرقابل‌پخش) قبل از خراب شدن شب فیلم متوجه می‌شوی. دکمه «بارگذاری» هم اگر تست نکرده باشی،
خودش اول تست می‌گیرد.

### 🌍 «پخش از طریق سرور» (برای ایران و خارج)

بعضی لینک‌ها به‌خاطر **CORS**، **تحریم/فیلتر جغرافیایی** یا **mixed-content** برای یکی باز
می‌شوند و برای دیگری نه. تیک **پخش از طریق سرور** ویدیو را از سرور تو عبور می‌دهد
(`/api/media/proxy`)، پس مرورگر بیننده فقط با دامنه خودت حرف می‌زند و فرقی نمی‌کند کاربر
کجای دنیا باشد. اگر تست تشخیص دهد که لینک مستقیم پخش نمی‌شود، این گزینه **خودکار روشن** می‌شود.

هدرهای `Range` در هر دو جهت منتقل می‌شوند، پس جابه‌جایی در فیلم (seek) سالم می‌ماند.

> ⚠️ **امنیت:** پراکسی روی همه‌ی آدرس‌های داخلی (`127.0.0.1`، `10.x`، `192.168.x`،
> `169.254.169.254` و…) بسته است و بعد از هر ریدایرکت دوباره بررسی می‌کند، تا کسی نتواند
> از سرورت برای خواندن شبکه داخلی سوءاستفاده کند (SSRF). اگر ویدیوهایت روی همان سرور یا
> شبکه محلی است، با `ALLOW_PRIVATE_MEDIA_HOSTS=1` می‌توانی این محدودیت را برداری — ولی
> فقط وقتی می‌دانی چه می‌کنی.

> 📌 **پهنای باند:** حالت پراکسی یعنی ترافیک ویدیو از سرور تو رد می‌شود. برای یک اتاق چندنفره
> مشکلی نیست، ولی روی سرور ضعیف با فیلم سنگین حواست به مصرف باشد.

> 🧲 **تورنت:** در مرورگر فقط تورنت‌هایی کار می‌کنند که تراکر **WebRTC** داشته باشند
> (مثل تراکرهای عمومی webtorrent). هر مگنتی لزوماً در مرورگر پخش نمی‌شود.

## 📞 تماس تصویری و صوتی / Video & voice calls

تماس با **WebRTC mesh** کار می‌کند: صدا و تصویر مستقیم بین مرورگرها رد و بدل می‌شود
و **هیچ‌وقت از سرور ما عبور نمی‌کند**. سرور فقط پیام‌های هماهنگی (SDP و ICE) را روی
همان Socket.IO موجود جابه‌جا می‌کند.

### چرا حداکثر ۴ نفر؟

در حالت mesh هر نفر باید برای *هر* نفر دیگر یک استریم جداگانه آپلود کند، پس پهنای
باند با مجذور تعداد افراد بالا می‌رود. با ~۶۰۰ کیلوبیت بر ثانیه به‌ازای هر استریم:

| تعداد نفرات | اتصال‌ها | آپلود لازم هر نفر | وضعیت |
|---|---|---|---|
| ۲ | ۱ | ۰٫۶ Mbps | عالی |
| ۳ | ۳ | ۱٫۲ Mbps | خوب |
| **۴** | **۶** | **۱٫۸ Mbps** | ✅ سقف پشتیبانی‌شده |
| ۵ | ۱۰ | ۲٫۴ Mbps | ⚠️ روی اینترنت موبایل ایران لنگ می‌زند |

بالای ۴ نفر برنامه اجازه ورود به تماس نمی‌دهد و هشدار می‌دهد (به‌جای اینکه کیفیت
برای همه بی‌سروصدا خراب شود). این عدد با `MAX_CALL_PEERS` قابل تغییر است.

### جلوگیری از glare

اگر دو طرف هم‌زمان `offer` بفرستند مذاکره به هم می‌ریزد. قانون ساده و قطعی:

> **فقط کسی که socket ID کوچک‌تری دارد offer می‌فرستد.**

هر دو مرورگر همین مقایسه را روی همان دو شناسه انجام می‌دهند و همیشه به نتیجه
مخالف می‌رسند، پس روی هر یال دقیقاً یک offer رد و بدل می‌شود. با ۴ نفر دقیقاً
۶ اتصال بدون تداخل ساخته می‌شود (در `test/call-engine.test.mjs` تست شده).

### جلوگیری از اکو

`getUserMedia` همیشه با این تنظیمات صدا می‌گیرد:

```js
{ echoCancellation: true, noiseSuppression: true, autoGainControl: true }
```

بدون این‌ها صدای فیلم از بلندگو وارد میکروفون می‌شود و حلقه بازخورد (feedback loop)
درست می‌کند — هم آزاردهنده است و هم باعث می‌شود ducking دائم فعال بماند.

## 🌐 TURN و NAT — مهم برای ایران

### وضعیت فعلی: فقط STUN

کد **با STUN تنها کار می‌کند** و در حدود **۸۵ تا ۹۰ درصد** موارد اتصال مستقیم
برقرار می‌شود. برای بقیه (NAT متقارن، CGNAT اپراتورهای موبایل، شبکه‌های سخت‌گیر)
یک رله TURN لازم است.

**این سرور نمی‌تواند خودش TURN باشد**، چون پشت پروکسی boxd است و پورت‌های UDP
مورد نیاز TURN را ندارد:

| پورت | کاربرد | وضعیت روی این سرور |
|---|---|---|
| `3478/udp` | TURN استاندارد | ❌ باز نیست |
| `5349/udp` | TURN روی TLS | ❌ باز نیست |
| `49152-65535/udp` | بازه رله | ❌ باز نیست |

پس TURN باید از یک سرویس بیرونی بیاید.

### افزودن TURN بدون تغییر کد

مقادیر از `.env` خوانده می‌شوند، پس هر وقت TURN داشتی فقط همین‌ها را اضافه کن و
سرویس را ری‌استارت کن:

```bash
TURN_URL=turns:relay.example.com:443?transport=tcp,turn:relay.example.com:3478
TURN_USER=myuser
TURN_PASS=mysecret
# اختیاری: جایگزینی STUNهای پیش‌فرض
# STUN_URL=stun:stun.cloudflare.com:3478
```

چند سرویس هم‌زمان؟ لیست‌ها را با کاما و متناظر بنویس:

```bash
TURN_URL=turns:a.example:443,turns:b.example:443
TURN_USER=userA,userB
TURN_PASS=passA,passB
```

> 🔑 **`turns:` روی پورت ۴۴۳ بهترین گزینه برای شبکه‌های سخت‌گیر است**، چون ترافیکش
> شبیه HTTPS معمولی به نظر می‌رسد و از فیلترینگ و بازرسی بسته (DPI) عبور می‌کند.
> اگر فقط می‌توانی یک ورودی بگذاری، همین را بگذار.

### سرویس‌های پیشنهادی

| سرویس | حجم رایگان | لینک |
|---|---|---|
| **Cloudflare Realtime TURN** (قبلاً Cloudflare Calls) | تا **۱۰۰۰ گیگابایت در ماه**، بعدش $۰٫۰۵ هر گیگ | <https://developers.cloudflare.com/realtime/turn/> |
| **Metered.ca / Open Relay** | تا **۲۰ گیگابایت در ماه**، روی پورت‌های ۸۰ و ۴۴۳ با TLS | <https://www.metered.ca/tools/openrelay/> |

STUN خود Cloudflare (`stun.cloudflare.com:3478`) رایگان و بدون محدودیت است و
به‌صورت پیش‌فرض در همین پروژه استفاده می‌شود.

### چرا endpoint جدا (`/api/ice`)؟

کلیدهای TURN **هیچ‌وقت داخل سورس جاوااسکریپت نمی‌روند**. مرورگر موقع شروع تماس
`GET /api/ice` می‌زند و آرایه `iceServers` را می‌گیرد. این یعنی:

- کسی نمی‌تواند کلیدها را از فایل JS بردارد و سهمیه‌ات را بسوزاند
- کلیدهای کوتاه‌مدت (short-lived) بدون build دوباره کار می‌کنند
- پاسخ با `Cache-Control: no-store` برمی‌گردد

### وقتی اتصال برقرار نمی‌شود

اگر اتصالی **۱۰ ثانیه** در حالت `connecting` بماند، به‌جای شکست بی‌صدا به کاربر
گفته می‌شود:

> «اتصال مستقیم ممکن نشد — TURN لازم است»

یک بار هم ICE restart خودکار انجام می‌شود (برای جابه‌جایی بین Wi-Fi و ۴G).

## 🔉 کم شدن هوشمند صدای فیلم (ducking)

وقتی کسی در تماس حرف می‌زند، صدای فیلم خودکار کم می‌شود و بعد از سکوت برمی‌گردد.
کاملاً با **Web Audio API** — **هیچ مدل AIای در کار نیست**، چون روی یک سرور
۲ هسته‌ای فقط تأخیر می‌سازد و اصلاً لازم نیست.

**مسیر سیگنال:** میکروفون (و صدای بقیه اعضا) → `AnalyserNode` → محاسبه RMS →
`GainNode` روی صدای فیلم.

اعداد آزمایش‌شده (در `public/assets/js/ducking.js`):

| پارامتر | مقدار | چرا |
|---|---|---|
| بازه نمونه‌برداری | `50ms` | واکنش سریع بدون بار اضافی روی CPU |
| آستانه RMS | `0.06` | سکوت اتاق، فن، تنفس و صدای فیلم از بلندگو فعالش نمی‌کنند؛ ولی پچ‌پچ و حرف عادی می‌کنند |
| کف صدا هنگام حرف زدن | `0.25` | صدا به ۲۵٪ می‌رسد، نه صفر — همچنان صحنه را دنبال می‌کنی |
| زمان نگه‌داشتن بعد از سکوت | `800ms` | **مهم‌ترین عدد:** مکث کوتاه وسط حرف صدا را بالا نمی‌پراند، وگرنه صدا مدام بالا-پایین می‌شود |
| ثابت زمانی `setTargetAtTime` | `0.15` | واکنش محسوس در ۱۵۰ میلی‌ثانیه، بدون صدای کلیک |

نتیجه: واکنش در ~۱۵۰ میلی‌ثانیه، و بدون نوسان آزاردهنده. کاربر می‌تواند حساسیت و
شدت کم‌شدن را از پنل 🎚️ کنار تماس تنظیم کند (در `localStorage` ذخیره می‌شود).

صدای فیلم بسته به منبع از سه راه کنترل می‌شود: `GainNode` واقعی (فایل محلی،
تورنت، HLS و لینک‌های same-origin)، `element.volume` (لینک‌های cross-origin که
Web Audio نمی‌تواند بخواندشان) و `setVolume()` (پلیر یوتیوب).

## 🧱 معماری / Architecture

```
server/
```

**چطور همگام می‌ماند:** سرور «منبع حقیقت» را نگه می‌دارد (`playing`, `time`, `updatedAt`).
هر کلاینت که وارد می‌شود، زمان پخش با توجه به زمان سپری‌شده برون‌یابی می‌شود، پس دقیقاً
روی فریم درست می‌افتد. میزبان هر ۵ ثانیه یک ضربان (heartbeat) می‌فرستد و اگر اختلاف
کلاینتی بیش از ۰٫۶ ثانیه شود، خودش را اصلاح می‌کند.

### رویدادهای Socket.IO

| رویداد | جهت | کاربرد |
|---|---|---|
| `room:join` | client → server | ورود به اتاق، دریافت وضعیت کامل |
| `player:source` | دوطرفه | تغییر منبع ویدیو (فقط میزبان) |
| `player:control` | client → server | پخش/توقف/seek (فقط میزبان) |
| `player:sync` | server → clients | اعمال وضعیت جدید |
| `player:request-sync` | client → server | همگام‌سازی دستی |
| `chat:message` / `chat:reaction` | دوطرفه | چت و ایموجی |
| `room:transfer-host` | client → server | واگذاری نقش میزبان |
| `call:join` / `call:leave` | client → server | ورود/خروج از تماس (بدون خروج از اتاق) |
| `call:peer-joined` / `call:peer-left` | server → clients | تغییر لیست شرکت‌کنندگان تماس |
| `call:state` / `call:peer-state` | دوطرفه | وضعیت میکروفون و دوربین |
| `call:offer` / `call:answer` | نقطه‌به‌نقطه | تبادل SDP (فقط بین دو نفر، نه broadcast) |
| `call:ice-candidate` | نقطه‌به‌نقطه | تبادل ICE candidate |

## 🔌 API

| متد | مسیر | توضیح |
|---|---|---|
| `POST` | `/api/rooms` | ساخت اتاق جدید |
| `POST` | `/api/media/detect` | تشخیص نوع لینک (بدون درخواست شبکه) |
| `POST` | `/api/media/probe` | تست پخش لینک + گزارش کامل |
| `GET` | `/api/media/proxy?url=` | پخش ویدیو از طریق سرور (با پشتیبانی Range) |
| `GET` | `/api/rooms/:id` | اطلاعات اتاق |
| `GET` | `/api/stats` | آمار زنده |
| `GET` | `/healthz` | health check |
| `GET` | `/ping` | بیکن سبک و CORS-باز برای تست دسترس‌پذیری دامنه |
| `GET` | `/api/config` | لیست دامنه‌ها + کشور کاربر (برای سوییچر دامنه) |
| `GET` | `/api/ice` | آرایه `iceServers` (STUN و در صورت وجود TURN) — بدون کش |

## 📝 نکات

- **فایل محلی آپلود نمی‌شود** — فقط خط زمانی همگام می‌شود، پس همه باید همان فایل را باز کنند.
- برای **تورنت** هم هر کلاینت خودش دانلود می‌کند؛ فقط زمان پخش همگام می‌شود.
- فرمت‌هایی مثل **mkv/avi** بسته به کدک ممکن است در مرورگر پخش نشوند — تست پخش هشدار می‌دهد.
- اتاق‌ها در حافظه‌اند؛ با ری‌استارت سرور پاک می‌شوند (برای این کاربرد کاملاً کافی است).
- اگر پشت Cloudflare هستی، WebSocket را در پنل فعال نگه دار.
- **تماس تصویری فقط روی HTTPS کار می‌کند** (یا `localhost`) — `getUserMedia` روی
  http ساده توسط مرورگر بلاک می‌شود.
- صدا و تصویر تماس **از سرور عبور نمی‌کند**؛ فقط SDP و ICE. پس تماس عملاً بار
  پهنای باندی روی سرور نمی‌گذارد.
- اگر بعضی کاربران وصل نمی‌شوند، تقریباً همیشه یعنی TURN لازم است —
  بخش [TURN و NAT](#-turn-و-nat--مهم-برای-ایران) را ببین.

## 🧪 تست‌ها

```bash
npm install
npm test
```

۵۰ تست، بدون نیاز به مرورگر:

- **`call-signalling.test.mjs`** — سرور واقعی بالا می‌آید و با کلاینت‌های واقعی
  Socket.IO تست می‌شود: ساخت مش ۴ نفره، رد کردن نفر پنجم، پاک شدن اتاق تماس
  موقع قطع ناگهانی، و اینکه کسی خارج از تماس نتواند سیگنالینگ بفرستد.
- **`call-engine.test.mjs`** — `RTCPeerConnection` شبیه‌سازی می‌شود و دو موتور به
  هم وصل می‌شوند: دقیقاً ۶ اتصال و ۶ offer برای ۴ نفر، بسته شدن کامل اتصال‌ها
  موقع خروج، تبدیل تصویری↔صوتی بدون renegotiation، و هشدار TURN بعد از ۱۰ ثانیه.
- **`ducking.test.mjs`** — الگوریتم با صدای ساختگی تست می‌شود: سکوت/فن/تنفس
  فعالش نمی‌کنند، پچ‌پچ می‌کند، و مکث کوتاه وسط حرف صدا را بالا نمی‌پراند.
