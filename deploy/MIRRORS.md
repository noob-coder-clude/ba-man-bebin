# چند دامنه، یک سرور · Multiple domains, one server

## چرا «ریدایرکت بر اساس IP» کار نمی‌کند؟

ایده‌ی «اگر کاربر ایرانی بود، بفرستش روی دامنه دیگر» یک ایراد بنیادی دارد:

> اگر دامنه‌ای در کشور کاربر **فیلتر** باشد، درخواست او **اصلاً به سرور تو نمی‌رسد**
> که بخواهی ریدایرکتش کنی. ریدایرکت فقط برای کسی کار می‌کند که از اول توانسته وصل شود —
> یعنی دقیقاً همان کسی که مشکلی نداشت.

ضمناً کاربر ایرانی با VPN، IP آلمان دارد؛ و کاربر خارج از ایران ممکن است IP ایران داشته باشد.
پس GeoIP اصلاً معیار درستی برای «چه چیزی برای این آدم باز می‌شود» نیست.

## راهی که واقعاً کار می‌کند

سه اصل:

1. **همه دامنه‌ها به یک سرور وصل‌اند** — بدون ریدایرکت. یک اتاق روی همه دامنه‌ها
   *همان* اتاق است (چون یک پروسه Node است، نه چند کپی).
2. **مرورگر خود کاربر تست می‌کند** — هر دامنه یک `/ping` سبک و CORS-باز دارد.
   مرورگر همه را موازی صدا می‌زند و می‌فهمد کدام واقعاً جواب می‌دهد.
   این تنها روشی است که فیلترینگ، DNS مسموم و قطعی را درست تشخیص می‌دهد.
3. **GeoIP فقط پیشنهاد است** — اگر Cloudflare هدر کشور را بدهد، از آن برای
   *پیشنهاد* استفاده می‌شود، نه اجبار.

نتیجه: لینک دعوت همیشه با دامنه‌ای کپی می‌شود که برای فرستنده کار می‌کند، و اگر
دامنه فعلی برای کسی باز نشود، خودش دامنه سالم را پیشنهاد می‌دهد.

## راه‌اندازی

### ۱. DNS
همه دامنه‌ها را به **همان IP سرور** اشاره بده (رکورد `A`).

### ۲. افزودن دامنه به سرور

```bash
sudo bash deploy/add-domain.sh dovom.com you@example.com
sudo bash deploy/add-domain.sh sevom.ir  you@example.com
```

این اسکریپت دامنه را به `server_name` انکس می‌کند، در `PUBLIC_DOMAINS` ثبتش می‌کند،
گواهی SSL می‌گیرد و سرویس را ری‌استارت می‌کند.

### ۳. یا دستی در `.env`

```env
PUBLIC_DOMAINS=film.com,watch.ir,bmb.net
DOMAIN_HINTS=IR=watch.ir,DE=film.com     # اختیاری
```

## Cloudflare (مفیدترین قطعه)

Cloudflare جلوی سرورت می‌نشیند و چند مشکل را هم‌زمان حل می‌کند:

- **IP سرورت مخفی می‌ماند** — اگر IP بلاک شود، فقط IP کلادفلر دیده شده، نه سرور تو.
- **هدر `CF-IPCountry`** رایگان است و همان چیزی است که برای پیشنهاد دامنه استفاده می‌کنیم.
- اگر یک دامنه بسوزد، دامنه بعدی را ظرف چند دقیقه بالا می‌آوری بدون تغییر سرور.

تنظیمات لازم:

| بخش | مقدار |
|---|---|
| DNS record | `A` → IP سرور، ابر **نارنجی** (Proxied) |
| SSL/TLS mode | **Full (strict)** — چون خودت Let's Encrypt داری |
| Network → **WebSockets** | حتماً **On** (وگرنه Socket.IO کار نمی‌کند) |
| Speed → Brotli | On |

> ⚠️ اگر «پخش از طریق سرور» را زیاد استفاده می‌کنی، ویدیو از کلادفلر رد می‌شود.
> پلن رایگان برای ترافیک سنگین ویدیو مناسب نیست — یا دامنه‌ی پراکسی را
> **DNS-only** (ابر خاکستری) کن، یا از پلن بالاتر استفاده کن.

## Render / Railway / Codespaces؟

| گزینه | مناسب برای | نکته مهم |
|---|---|---|
| **سرور خودت** | ✅ میزبان اصلی | کنترل کامل، بدون خواب، پهنای باند مشخص |
| **Cloudflare** | ✅ جلوی سرور | مخفی‌سازی IP + هدر کشور + WebSocket |
| **Render** | آینه پشتیبان | پلن رایگان بعد ۱۵ دقیقه می‌خوابد و ۳۰-۵۰ ثانیه بیدار شدنش طول می‌کشد؛ برای شب فیلم بد است. پلن `starter` مشکلی ندارد. |
| **Railway** | آینه پشتیبان | عملاً رایگان نیست (فقط ~۱ دلار اعتبار ماهانه) ولی نمی‌خوابد |
| **GitHub Pages** | ❌ نمی‌شود | فقط فایل استاتیک؛ نه Node اجرا می‌کند نه WebSocket |
| **Codespaces** | ❌ نمی‌شود | محیط توسعه است، نه هاست؛ خودش هم می‌خوابد |

فایل‌های `render.yaml` و `railway.json` آماده‌اند، ولی **حالت درست این است که سرور خودت
میزبان اصلی باشد** و بقیه فقط آینه‌ی پشتیبان.

> ⚠️ نکته مهم درباره آینه‌ها: اتاق‌ها در حافظه‌ی همان پروسه‌اند. یعنی اگر Render را
> به‌عنوان آینه‌ی **جداگانه** بالا بیاوری، اتاق‌هایش از سرور اصلی جدا خواهند بود.
> برای اینکه واقعاً «یک سرور، چند دامنه» باشد، همه دامنه‌ها باید به **همان یک ماشین**
> اشاره کنند. آینه‌ی مستقل فقط وقتی معنی دارد که سرور اصلی کلاً از دسترس خارج شده باشد.
